# General-Spec

一份可复用的中文 [AGENTS.md](./AGENTS.md)，用于为编码代理提供项目协作规范。将它放入项目后，可统一代码修改、架构边界、测试验证和交付方式，并按项目实际情况补充具体约定。

模板不绑定特定语言、框架、包管理器或分支名称，要求代理从当前仓库的文档、配置和既有实现中确认工作依据。

## 用途

- **统一协作方式**：明确修改范围、完成标准和沟通要求，保留已有工作。
- **保持代码一致性**：遵循现有架构、依赖方向、代码风格和公共接口约定。
- **规范验证与交付**：根据变更风险选择检查方式，如实说明验证结果和未完成事项。
- **沉淀团队约定**：将反复使用的规则保存在仓库中，减少每次任务都要重新说明的内容。

## 文件说明

| 文件 | 面向读者 | 内容 |
| --- | --- | --- |
| [AGENTS.md](./AGENTS.md) | 编码代理及维护者 | 在项目中执行任务时应遵循的协作规则 |
| [README.md](./README.md) | 使用者及维护者 | 模板的用途、接入方法和维护建议 |

## 快速开始

### 1. 放入项目根目录

打开本仓库的 [AGENTS.md](./AGENTS.md)，下载或复制其完整内容，以 UTF-8 编码保存为目标项目根目录下的 `AGENTS.md`。文件名保持大写。

```text
your-project/
├── AGENTS.md
├── README.md
└── src/
```

如果项目已经有 `AGENTS.md`，先阅读并合并适用规则，保留现有的项目约定。

### 2. 补充项目实际信息

通用规则可直接作为基础。为了让代理更快找到正确的工作方式，建议补充以下信息：

| 信息 | 建议写明的内容 |
| --- | --- |
| 项目结构 | 主要模块、入口、架构说明和关键文档的位置 |
| 开发环境 | 运行时、工具版本、包管理器和环境准备方式 |
| 检查与测试 | 实际命令、执行目录、必要前置条件和 CI 要求 |
| 代码生成 | 源定义位置、生成目录、生成命令和产物提交要求 |
| Git 与发布 | 默认分支、PR 目标、提交格式和现有发布流程 |
| 特殊边界 | 数据迁移、兼容性要求、外部服务及需要明确授权的操作 |

将这些内容添加到文件末尾的“项目补充约定”中，或融入对应章节。涉及 UI、队列或持久化等条件性规则时，按项目实际功能选用。

### 3. 在编码工具中使用

在目标项目中启动支持 `AGENTS.md` 的编码代理，并确认它读取了文件。可以先发出以下任务：

```text
开始修改前，请读取适用于本次任务的 AGENTS.md，简要列出关键约定，
并从仓库配置中确认相关检查命令和执行目录。
```

以 Codex 为例，它会在开始工作前读取指令文件，并按项目根目录到当前工作目录的路径组合项目规则。具体发现顺序和配置见 [OpenAI Docs：AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

其他工具的自动读取能力、作用范围和刷新方式，以对应工具的文档为准。若工具不自动读取，可在任务中明确指定文件，或将相关内容放入该工具支持的项目指令配置。

### 4. 用一次小任务确认效果

选择范围明确的任务，检查代理是否遵循了已有风格、保留了无关修改、执行了适当验证，并如实报告结果。发现规则含糊或与项目冲突时，及时调整文件。

## 多目录项目如何使用

根目录文件放通用约定；不同模块需要不同规则时，在对应目录增加 `AGENTS.md`，集中说明该模块的补充要求。

```text
your-project/
├── AGENTS.md                 # 项目通用约定
├── frontend/
│   └── AGENTS.md             # 前端组件、主题和交互测试约定
└── backend/
    └── AGENTS.md             # 接口、数据模型和迁移约定
```

按本模板的约定，更具体目录中的规则可细化或覆盖通用规则，同时遵循平台约束和用户明确要求。实际加载哪些文件由工具决定；使用 Codex 时，应从相应工作目录启动，并核对已加载的规则来源。相关机制见 [OpenAI Docs：指令发现与合并](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance)。

## 规则覆盖范围

模板包含 12 个部分：

| 领域 | 主要内容 |
| --- | --- |
| 工作依据与范围 | 指令作用范围、仓库证据、最小修改和已有工作保护 |
| 架构与契约 | 依赖边界、公开接口、生成代码和产物同步 |
| 实现质量 | 可读性、输入校验、错误处理和异步资源管理 |
| 数据与状态 | 事务、幂等、重试、事件及并发保证的边界 |
| 界面与调试 | 语义主题、真实组件示例、可访问性和现场状态保护 |
| 验证与交付 | 风险匹配的测试、检查结果、提交发布和完成说明 |

## 维护建议

- 将项目中的 `AGENTS.md` 纳入版本控制，让规则变更与代码变更一样可审阅。
- 环境、脚本、架构或发布流程发生变化时，同步更新相关约定。
- 保持规则具体、简洁、可执行；已有详细文档时，引用其位置，减少重复维护。
- 从本仓库更新模板时，先比较差异，再合并所需内容，保留项目补充规则。
- 修改指令后，按工具要求重新启动或开启新会话，并确认实际读取的内容。Codex 的刷新与排查方法见 [OpenAI Docs：验证配置](https://learn.chatgpt.com/docs/agent-configuration/agents-md#verify-your-setup)。
